# Claude frontend handoff — BizLeap Lead Management System

Use the accompanying `docs/api-contract.md` (v1.0) as the source of truth. You own frontend architecture, DESIGN.md and visual design: balanced professional SaaS CRM, responsive at 1440px, 768px and 375px. ChatGPT owns backend and contract. Do not implement an alternative backend, rename API fields or change endpoints independently.

- React + Vite, Tailwind CSS, Recharts. Browser base URL `/api` (Vite proxy to Express port 5000); use `VITE_API_BASE_URL=/api` and relative requests. Authentication is HTTP-only cookie `access_token`, not a bearer token. Use `credentials: 'same-origin'`; do not read or store JWTs. No public registration.
- `POST /api/auth/login` body `{email,password}` -> 200 `{success:true,data:{user:{_id,name,email,role}}}`. `GET /api/auth/me` returns same shape. `POST /api/auth/logout` -> 200 `{success:true,data:null}`. Startup session check, protected route loading state, redirect on 401 except login failure (show error).
- Lead object: `_id`, `fullName`, `email`, `phone`, `companyName`, `leadSource`, `leadStatus`, `createdAt`, `updatedAt`. Dates are ISO UTC; ID is `_id`, not `id`.
- `GET /api/leads?search=&status=&source=&page=1&limit=10` (omit blank filters). Response `{success:true,data:[...leads],pagination:{page,limit,total,totalPages}}`. Default newest first, page 1, limit 10. Search name/email/phone/company; debounce ~300 ms; reset page on filters. `All` is UI only; omit status/source to show all.
- `POST /api/leads` -> 201; `GET /api/leads/:id` -> 200; `PUT /api/leads/:id` -> 200. All return `{success:true,data:lead}`. POST and PUT body: `{fullName,email,phone,companyName,leadSource,leadStatus}`; POST may omit status (defaults New), PUT requires all six. Status-only updates still send all six fields. Never send `_id` or timestamps in request bodies. `DELETE /api/leads/:id` -> 200 `{success:true,data:null}`; confirm deletion.
- Statuses (exact case): New, Contacted, Interested, Converted, Lost. Sources: Website, Instagram, LinkedIn, Referral, Advertisement, Cold Calling. Use select controls for these enums.
- `GET /api/dashboard/summary` -> `{success:true,data:{totalLeads,newLeads,contactedLeads,interestedLeads,convertedLeads,lostLeads,byStatus:[{status,count}],bySource:[{source,count}],leadsOverTime:[{date,count}]}}`. Trend has 30 UTC dates (`YYYY-MM-DD`), oldest first, zero-filled. Breakdown arrays contain all enum categories, even zeros. Conversion rate = convertedLeads / totalLeads * 100 (zero when total is zero). Recent leads: `/api/leads?limit=5`. Refetch dashboard and table after mutations. Do not hardcode counts.
- Error format `{success:false,error:{code,message,fields?}}` where fields maps names to strings. Handle validation (400), bad login/session (401), forbidden (403), not found (404), throttling (429), network failures and server errors. Show loading, empty and error states.
- Initial fixture has exactly 40 fictional leads, New 12, Contacted 10, Interested 8, Converted 6, Lost 4. Mock APIs may be used during UI development only if they conform to this contract; remove or disable mocks before submission. No runtime dependency on fixture statistics.

Do not add new backend requirements without checking with ChatGPT/user first. No follow-up date, reminder or task API is part of this MVP. The contract is a planned interface, not yet a running server.
